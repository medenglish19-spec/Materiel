# نسخة Windows

المنتج هو مُثبّت Windows باسم **تسيير ومحاسبة العتاد**، ويحتوي البرنامج التنفيذي `Materiel.exe` مع ملفات القوالب والملفات الثابتة والترحيلات اللازمة للتشغيل دون تثبيت Python.

يستهدف هذا الإصدار Windows 10/11 ‏64-bit، ويتطلب التثبيت بصلاحيات مسؤول. لا يدعم Windows 32-bit أو الإصدارات الأقدم من Windows 10. لا يمكن ضمان عمله على كل جهاز/صورة Windows؛ يجب التحقق من كل مثبت إصدار على Windows نظيف ضمن مصفوفة الدعم.

## التخزين والتحديث

- يضع المُثبّت قاعدة البيانات افتراضيًا في `%ProgramData%\Materiel\data\fleet_assets.db`، وهو مسار ثابت لا يعتمد على وجود قرص D. يمكن تجاوز المسار بتعيين `MATERIEL_DATA_DIR`.
- يعمل EXE على المضيف المحلي فقط، ويبدأ بالمنفذ 8000 ثم يختار منفذًا متاحًا تلقائيًا عند انشغاله. لا يعتمد على متغيرات التطوير `DATABASE_URL` أو `SECRET_KEY` أو `APP_ENV` أو `DEV_DISABLE_AUTH` أو `APP_HOST` أو `APP_PORT` أو `LOG_DIR` الموجودة على جهاز المستخدم.
- يُحفظ المسار في `materiel-data-dir.txt` بجانب البرنامج. لا يستبدل التحديث هذا الملف ولا يضمّن قاعدة بيانات ضمن ملفات البرنامج.
- ينشئ المُثبّت نسخة احتياطية قبل الترقية. وينشئ التطبيق نسخة SQLite ثانية بعد التحقق من سلامتها قبل أي ترحيل؛ إذا فشل الترحيل، يستعيد القاعدة تلقائيًا من النسخة.
- لا يحذف إلغاء التثبيت مجلد البيانات.
- عند أول تشغيل لقاعدة بيانات إصدار الإنتاج، يطلب التطبيق إنشاء كلمة مرور مدير خاصة لا تقل عن 12 خانة؛ لا يستخدم `admin/Admin@123` كبيانات دخول افتراضية في النسخة المثبتة. تظهر صفحة الإعداد محليًا فقط، وبعد إنشاء المدير يعود التطبيق إلى تسجيل الدخول المعتاد.
- لا تغيّر التحديثات كلمات مرور الحسابات القائمة. إذا كانت قاعدة البيانات قديمة وما زالت تستخدم كلمة المرور المنشورة، غيّرها من صفحة المستخدمين بعد التحديث.
- تخزن صور الطرازات وقطع الغيار في مجلد البيانات، وتُنقل الصور القديمة إليه بالنسخ فقط؛ الملفات الموجودة لا تُستبدل.
- تُقرأ أسماء المؤسسة والتطوير والإشراف من `splash-screen/config.json`، ويُقرأ الشعار من الملف المحدد في `logo_file`. كل بناء يجمع جميع ملفات وصور مجلد `splash-screen` الحالي؛ لذلك تنعكس أحدث تعديلات الإعدادات أو استبدال الشعار أو إضافة ملفات عند تثبيت النسخة الجديدة. لا تتغير نسخة مثبّتة تلقائيًا؛ يلزم بناء مثبت جديد ثم تثبيته.

## البناء

يتطلب البناء Windows 10/11 ‏64-bit وPython 3.14 وInno Setup 6. شغّل من جذر المستودع بصلاحيات مستخدم عادية:

```powershell
PowerShell -ExecutionPolicy Bypass -File .\windows\build_windows.ps1
```

ينشئ السكربت بيئة بناء معزولة وملفات وسيطة ومُثبّت الإصدار تحت `%LOCALAPPDATA%\Materiel\` افتراضيًا. يمكن تمرير `-BuildDirectory` و`-ReleaseDirectory` لتحديد مسارات أخرى. يتحقق البناء من تطابق الإصدار في `windows/version.txt` و`splash-screen/config.json`، ولا يضمّن قاعدة البيانات المحلية أو الصور المرفوعة.

## اختبار المثبّت

بعد البناء، شغّل اختبارًا طرفًا إلى طرف في تثبيت وقاعدة بيانات مؤقتين:

```powershell
$installer = Join-Path "$env:LOCALAPPDATA\Materiel\release" "Materiel-Setup.exe"
$buildRoot = Get-ChildItem "$env:LOCALAPPDATA\Materiel\build" -Directory | Sort-Object LastWriteTime -Descending | Select-Object -First 1
$python = Join-Path $buildRoot.FullName "venv\Scripts\python.exe"
& .\windows\smoke_test_installer.ps1 -InstallerPath $installer -PythonExecutable $python
```

يتطلب الاختبار حسابًا يستطيع الموافقة على مطالبة UAC. يثبّت الملف في مسار QA مؤقت تحت `%LOCALAPPDATA%\Materiel\smoke-tests`، ويحجز المنفذ 8000 لمحاكاة تعارضه، ثم يفحص اختيار منفذ بديل وواجهة GUI بلا Console وصفحات HTTP وتسجيل الدخول والهوية والشعار وصلاحيات الملفات. كما يختبر ترقية مخطط قديم مع نسخة احتياطية وعلامة بيانات، ثم إلغاء التثبيت وإعادة التثبيت للتأكد من بقاء قاعدة البيانات والمرفقات. يترك مجلد QA وسجلاته للمراجعة؛ لا يحذفها تلقائيًا.

يفحص سير عمل GitHub Actions الاختبارات وبناء المثبّت واختبار تثبيته على Windows Server 2022 x64؛ وهو لا يغني عن تجربة Windows 10/11 نظيفة على أجهزة فعلية، ولا عن توقيع المثبّت رقميًا.
