# كتالوج قطع الغيار

## دليل المستخدم

افتح **قطع الغيار → كتالوج قطع الغيار**. تعرض الصفحة القطع الموجودة في سجل `spare_parts` نفسه، بما فيها السجلات القديمة، وتتيح البحث والتصفية حسب التصنيف والشركة والمصدر والحالة. يمكن إضافة قطعة يدويًا أو تعديلها وأرشفتها. الأرشفة لا تحذف القطعة ولا تمس الطلبات أو حركاتها أو سجلات الإصلاح.

رمز الكتالوج الداخلي ينشأ تلقائيًا. المرجع الوارد من المصنع يُحفظ كمرجع خارجي منفصل؛ لذلك لا تُنشأ حركة استلام أو كمية مخزون من إدخال القطعة أو استيراد الكتالوج. الاسم الأصلي يبقى منفصلًا عن الاسمين العربي والفرنسي، ولا ينشئ النظام ترجمة آلية.

لإضافة صورة، استخدم JPEG أو PNG أو WebP. الحد الأقصى 5 ميغابايت و50 مليون بكسل. يعاد ترميز الصورة محليًا لإزالة بياناتها الوصفية؛ اسم الملف المخزن عشوائي ولا يعتمد على اسم الملف الذي رفعه المستخدم.

### استيراد ملف

1. افتح **استيراد كتالوج** واختر ملفًا واحدًا.
2. راجع المعاينة وعدّل حقول الصف مباشرة، ثم ألغِ اختيار الصفوف غير المناسبة.
3. لا تُضاف المطابقات المرجعية آليًا. لا تفعّل خيار «قطعة مستقلة» إلا بعد التأكد من أنها قطعة مختلفة.
4. اعتمد الصفوف المحددة. يمكن إرسال الدفعة نفسها مرة أخرى بأمان؛ تُحفظ نتيجة الدفعة ولا يعاد إنشاؤها.

تُقبل أسماء الأعمدة الشائعة بالإنجليزية والفرنسية والعربية، بما فيها صيغ مثل «Code article» و«Désignation pièce» و«رقم الصنف». يبحث المحلل عن صف العناوين ضمن أول 20 صفًا، ويتجاوز أسطر العنوان التمهيدية ويعرض تحذيرًا عنها. في الملف الذي لا يحتوي عناوين معروفة، تُفسر أول خانتين كمرجع ثم اسم مع تحذير؛ راجع الحقول في المعاينة وصححها قبل الاعتماد. الحد 10 ميغابايت و1000 صف. تُحذف الملفات المؤقتة بعد التحليل، ولا يُحفظ ملف المصدر في مجلد عام.

## الصيغ التي اختُبرت

| الصيغة | الحالة الفعلية | الملاحظات |
|---|---|---|
| CSV | مدعومة ومختبرة | UTF-8 وUTF-8 BOM وترميز فرنسي/غربي؛ فواصل comma وsemicolon وtab وpipe. |
| XLSX | مدعومة ومختبرة | كل الأوراق، قيم الخلايا فقط، صيغ Excel لا تُنفذ، وتنسيق الأصفار مثل `000123` يحافظ على الأصفار. |
| DOCX | مدعومة ومختبرة | استخراج محلي لـ OpenXML من الفقرات والجداول؛ لا تُنفذ وحدات ماكرو. |
| XML | مدعومة ومختبرة | صفوف العناصر ذات الخلايا النصية المباشرة؛ ليست محولًا خاصًا بمورّد. |
| HTML/HTM | مدعومة ومختبرة | جداول HTML المحلية فقط؛ لا تُنفذ JavaScript أو موارد خارجية. |
| ZIP | مدعومة ومختبرة | ملف كتالوج واحد بالضبط (CSV أو XLSX أو PDF أو DOCX أو XLS أو XML أو HTML)، مع صور اختيارية مربوطة فقط عندما يطابق اسم الصورة مرجع القطعة حرفيًا بعد تطبيع محدود. |
| PDF | دعم محدود ومختبر | يعيد استخدام مستخرج المستندات الحالي. من دون pypdf أو Docling، يقرأ فقط نصوص PDF البسيطة غير المضغوطة التي تستخدم `Tj/TJ`. ملفات PDF المعقدة تحتاج pypdf أو Docling. لا يستخرج fallback الجداول المرئية أو الرسومات. |
| XLS | غير متاح في بيئة الاختبار | يحتاج xlrd؛ المكتبة غير مثبتة في المتطلبات/بيئة التنفيذ. تظهر رسالة توضح ذلك. استخدم XLSX أو CSV. |
| PDF ممسوح/OCR | غير متاح | لم يُثبت PaddleOCR أو نماذجه. لا تُعتمد نتائج OCR ولا ينزل النظام نماذج تلقائيًا. |
| صورة منفردة | ليست كتالوجًا | ترفع كصورة قطعة من نموذج الإضافة أو التعديل. صور ZIP لا ترتبط إلا بمرجع اسم مطابق. |

لم يُختبر DOCX مع ملفات كبيرة أو جداول معقدة، ولا PDF ممسوح ضوئيًا. ملفات ZIP ذات الأرشيفات المتداخلة أو الروابط الرمزية أو مسارات الاجتياز مرفوضة. الحدود: 100 ملف، 30 ميغابايت مفكوك، ونسبة ضغط قصوى 100:1؛ الصور المضمنة محدودة بـ50 صورة و5 ميغابايت إجمالًا و2 ميغابايت للصورة.

## البيانات والتوافق

- `spare_parts` يبقى هوية القطعة الأساسية، وتظل العلاقات التاريخية في `repair_parts` وطلبات وحركات قطع الغيار مرتبطة بالمعرّف نفسه.
- يضيف `spare_part_catalog_details` الأسماء اللغوية والشركة والتصنيف والمصدر والصورة والحالة.
- يدعم `spare_part_categories` شجرة تصنيف ذاتية المرجع، و`spare_part_catalog_references` يحتفظ بمراجع المصنع ومصدرها.
- يحتفظ `spare_part_catalog_imports` ببصمة الملف وحالة الدفعة ومعاينتها وملخص النتيجة لمنع إعادة التطبيق غير المقصودة.
- الاستيراد لا ينشئ رصيدًا، ولا يكتب في جداول الاستلام أو التوزيع أو الإرجاع.

الصور تحفظ في `static/uploads/spare-parts/`، والقاعدة تحفظ مسارًا نسبيًا عامًا للصورة فقط. النسخ الاحتياطي الكامل للكتالوج يتطلب قاعدة البيانات **ومجلد الصور معًا**. استخدم آلية النسخ الاحتياطي المعتمدة في Materiel لقاعدة البيانات، وخذ نسخة متزامنة من مجلد الصور؛ عند الاستعادة أعد كليهما إلى البيئة نفسها.

## دليل المطور

- استقبال الملفات وحد الحجم المشترك في `app/modules/document_import/upload.py`، ويستخدمه مستورد خصائص الطراز والكتالوج.
- استخراج خصائص الطراز يبقى في `app/modules/document_import/`. كتالوج القطع يضيف محولات مستقلة وتطبيعًا ومطابقة في `app/modules/spare_parts_catalog/services.py`، ويستدعي `document_import.extraction.extract_document` للصيغ المستندة إلى المستند.
- واجهة الكتالوج في `app/modules/spare_parts_catalog/router.py` وقوالبه في `templates/`. يسجل المسارات في `web/main.py`.
- أضف محولًا جديدًا إلى `_parse_content` أو استخرج Adapter مستقلًا، وأعد صفوفًا إلى الحقول الداخلية نفسها. أبقِ فحص التوقيع والحدود والصفوف والتحقق من الصور، واكتب اختبارًا فعليًا لملف حقيقي قبل إعلان الصيغة مدعومة.
- المطابقة المؤكدة تعتمد المرجع والشركة، وتشابه الاسم تحذير فقط. لا يدمج النظام قطعتين آليًا. المستخدم يستطيع السماح بإنشاء قطعة مستقلة حتى عند وجود تعارض واضح.
- التثبيت الجديد يتضمن Pillow لمعالجة الصور. XLS قديم يحتاج إضافة xlrd عند الحاجة. PDF المتقدم يحتاج pypdf أو Docling اختياريًا؛ OCR غير مفعّل.

### ترحيل واختبار

أُضيف الترحيل `20261019_spare_parts_catalog` بعد رأس `20261018_tire_battery_asset_receipts`. يطبّق على قاعدة Materiel مختومة/مهيأة فقط. لا تشغّل `alembic upgrade head` على قاعدة فارغة؛ اتبع مسار التهيئة المعتمد في `AGENTS.md`. خذ نسخة احتياطية قبل ترحيل بيئة تشغيلية، ولا تطبق ترحيل الاختبار على قاعدة المستخدم.

تشغيل الاختبارات ذات الصلة من جذر المشروع:

```powershell
python -m pytest -q tests/test_spare_parts_catalog.py tests/test_spare_parts_catalog_migration.py
python -m pytest -q tests/test_document_import_offline.py tests/test_document_import_fuzzy.py tests/test_document_import_pdf.py tests/test_document_import_integration.py tests/test_document_import_behavioral.py
```

الحدود المعروفة: المعاينة تسمح بتصحيح القيم لكل صف، لكنها لا توفر شاشة مستقلة لمطابقة عمود غير معروف. لا يوجد تصدير CSV لنتيجة الدفعة أو دمج/تحديث جماعي. PDF غير المكتبي استخراج تقريبي للنص ولا يضمن تنظيم الأعمدة؛ راجع كل صف قبل الاعتماد.
